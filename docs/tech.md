## Из чего собрано

| Слой | Чем сделан | Зачем так |
|---|---|---|
| Интерфейс | React 19 + TypeScript + Vite | Прототип был одним HTML-файлом со строками стилей в JS; теперь это компоненты и CSS |
| API и хранилище | Node 22 + Fastify 5 + SQLite (better-sqlite3, WAL) | Синхронный драйвер и транзакции: разметка суток не должна разъезжаться |
| Общий домен | `shared/` — чистые функции на обе стороны | Раскатка дней и правила перекрытий обязаны считаться одинаково в UI и на сервере |
| Дизайн-система | `_ds/shff-design-system-*` | Вендорится как есть; продукт расширяет её у себя, а не правит |
| Упаковка | Один образ: Node раздаёт и API, и собранный SPA | Никаких сайдкаров с nginx — меньше деталей, меньше поломок |

```
shared/          домен: время, перекрытия, раскатка, метрики, валидация
server/          Fastify, SQLite, миграции, сценарии, маршруты
web/             React-интерфейс, стили продукта
_ds/             дизайн-система SHFF (вендор) + самохостящиеся шрифты
scripts/         dev.mjs, fetch-fonts.mjs, smoke.mjs
docs/            эта страница и скриншоты
prototype/       исходный набросок, из которого всё выросло
```

В базе лежат блоки, категории, шаблоны суток, настройки интерфейса, аккаунт администратора и журнал
операций для отмены. В localStorage не лежит ничего — открыл с телефона, увидел то же самое.

## Запуск

### Docker

```bash
docker compose pull && docker compose up -d
docker compose logs -f planner
```

Собрать из исходников вместо готового образа — `docker compose up -d --build`.
База — в томе `shff-planner_planner-data`, том переживает пересборку образа.

### Без Docker

Нужен Node 22+.

```bash
npm install
npm run build
SHFF_DATA_DIR=./data npm start
```

### Разработка

```bash
npm run dev        # API на :8787 с перезапуском, интерфейс на :5173
npm test           # домен, API и рендер интерфейса — 89 тестов
npm run typecheck  # tsc по обоим проектам
npm run smoke      # 22 проверки живого экземпляра
npm run fonts      # перекачать веб-шрифты с Google Fonts и положить локально
```

Тесты: `shared/test` и `server/test` (домен и API через `app.inject`), `web/src/App.test.tsx`
(рендер интерфейса в jsdom).

## Переменные окружения

Все необязательные — сервис поднимается с пустым окружением. Полный список с комментариями —
в [`.env.example`](../.env.example).

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SHFF_HOST_PORT` | `8787` | Порт на хосте (только для compose) |
| `SHFF_PORT` | `8787` | Порт внутри контейнера |
| `SHFF_DATA_DIR` | `/data` | Где лежит `planner.db` |
| `SHFF_AUTH_PASSWORD` | — | **Аварийный ключ.** Пусто — доступом распоряжается панель. Если задан, перебивает базу: вход только по нему, из панели замок не меняется |
| `SHFF_AUTH_LOGIN` | `admin` | Логин для аварийного ключа |
| `SHFF_SESSION_SECRET` | — | Подпись cookie. Пусто — сгенерируется в `$SHFF_DATA_DIR/session.key` |
| `SHFF_SEED` | `none` | `demo` — засеять примерную неделю вокруг сегодня при первом запуске |
| `SHFF_LOG_LEVEL` | `info` | `fatal … trace`, `silent` |
| `SHFF_TRUST_PROXY` | `false` | Включи за reverse proxy: от этого зависит, чей IP попадёт в счётчик попыток входа |
| `SHFF_IMAGE` | `heisenberg4441/shff-planner:latest` | Какой образ поднимает compose |
| `TZ` | `Europe/Moscow` | Только логи и `created_at`: даты блоков хранятся как `YYYY-MM-DD` без зоны |

## Доступ

Первый заход в панель спрашивает один раз: аккаунт администратора или свободный вход. Логин и пароль
(scrypt, 16 МБ памяти на проверку) лежат в той же базе, что и разметка. Пока выбор не сделан, API
отвечает `401 setup_required` на всё, кроме `/api/health` и `/api/auth`.

Дальше в настройках можно поставить пароль, сменить его или снять — смена и снятие требуют текущий
пароль и гасят все выданные сессии (в cookie вшита версия замка). Попытки входа считаются:
10 промахов за 5 минут — `429`.

Забыл пароль: задай `SHFF_AUTH_PASSWORD` в окружении, войди аварийным ключом, поставь новый
через настройки и убери переменную.

## API

Всё под `/api`, ответы — JSON, ошибки в виде `{ "error": "код", "message": "человеческий текст" }`.
Мутации возвращают `{ days, blocks, op, revision, partial }`: что изменилось и чем это откатить.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | Живость, версия, размер базы. Открыт всегда |
| `GET` | `/api/bootstrap?view=day&date=…` | Всё для загрузки интерфейса одним запросом |
| `GET` | `/api/blocks?from=…&to=…` | Блоки за диапазон (или `?view=week&date=…`) |
| `POST` | `/api/blocks` | Поставить блок. `overlap: trim⎮reject` |
| `PATCH` | `/api/blocks/:id` | Правка; можно менять дату — блок переедет |
| `DELETE` | `/api/blocks/:id` | Снять блок |
| `GET` `PUT` | `/api/days/:date` | Прочитать сутки / заменить целиком (`blocks` или `templateId`) |
| `POST` | `/api/duplicate` | Раскатка: `sourceDate`, `scope`, `mode`, `weekdays`, `blockIds` |
| `POST` | `/api/undo` | Отменить операцию (`opId` или последнюю) |
| `GET` `PATCH` | `/api/settings` | Настройки интерфейса |
| `GET` `POST` `PATCH` `DELETE` | `/api/categories[/:id]` | Категории. Занятую удалить нельзя |
| `GET` `POST` `PATCH` `DELETE` | `/api/templates[/:id]` | Шаблоны суток. `POST {fromDate}` снимает шаблон с суток |
| `GET` `POST` | `/api/export`, `/api/import` | Бекап |
| `GET` | `/api/events` | Поток изменений (SSE) для живого обновления вкладок |
| `GET` | `/api/auth` | Состояние доступа. Открыт всегда |
| `POST` | `/api/auth/setup` | Первый запуск: `{mode:'account',login,password}` или `{mode:'open'}`. Потом — `409` |
| `POST` | `/api/auth/login`, `/api/auth/logout` | Вход и выход |
| `PATCH` | `/api/auth` | Сменить замок: поставить пароль, сменить (`currentPassword`) или снять |

Пример — поставить блок и сразу его отменить:

```bash
OP=$(curl -sS -X POST localhost:8787/api/blocks -H 'Content-Type: application/json' \
  -d '{"date":"2026-07-30","start":480,"end":720,"title":"Deep: миграция","category":"deep"}' \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).op.id))")
curl -sS -X POST localhost:8787/api/undo -H 'Content-Type: application/json' -d "{\"opId\":\"$OP\"}"
```

## Бекап и перенос

Бекап — один JSON со всем содержимым базы:

```bash
curl -o planner-backup.json http://localhost:8787/api/export
```

Восстановление — через `// ДАННЫЕ` в настройках или запросом:

```bash
curl -X POST http://localhost:8787/api/import \
  -H 'Content-Type: application/json' \
  --data-binary @planner-backup.json     # режим по умолчанию — заменить всё
```

Импорт тоже отменяем: перед записью пишется снимок.

Можно бекапить и сам том. SQLite работает в WAL, поэтому копию снимай при остановленном контейнере:

```bash
docker compose stop planner
docker run --rm -v shff-planner_planner-data:/data -v "$PWD:/out" alpine \
  tar czf /out/planner-data.tgz -C /data .
docker compose start planner
```

## За reverse proxy

Планировщик слушает обычный HTTP и ничего не знает про домены. Caddy:

```caddy
planner.example.org {
  reverse_proxy 127.0.0.1:8787
}
```

Для nginx важно не буферизовать поток событий, иначе живые обновления приедут пачкой:

```nginx
location / {
  proxy_pass http://127.0.0.1:8787;
  proxy_http_version 1.1;
  proxy_set_header Connection '';
  proxy_buffering off;          # SSE
  proxy_read_timeout 1h;
}
```

Если сервис виден из интернета — поставь пароль и включи `SHFF_TRUST_PROXY=true`.

## Сборка и публикация

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) на каждый push в `master`:

1. типы (`npm run typecheck`), тесты (`npm test`), сборка (`npm run build`);
2. сборка образа и **прогон смоука по собранному образу** — контейнер поднимается прямо в раннере,
   ему выбирается свободный вход, и `scripts/smoke.mjs` проверяет 22 сценария;
3. только после зелёного смоука — публикация в Docker Hub.

Теги: `latest`, версия из `package.json`, короткий SHA коммита. Git-тег `v1.2.3` добавляет семверные
`1.2.3` и `1.2`. Пул-реквесты собирают и проверяют образ, но ничего не публикуют.

Нужны два секрета репозитория: `DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN` (Read & Write).

Образ собирается под `linux/amd64`. Для одноплатников в шаге публикации меняется одна строка —
`platforms: linux/amd64,linux/arm64`; первая сборка под ARM будет долгой: `better-sqlite3` не публикует
готовых бинарей и компилируется из исходников под эмуляцией.

## Решения, которые стоит знать

**Сутки — это разбиение, а не список.** Поэтому перекрытия не запрещены, а разрешаются подрезкой:
запрет заставлял бы вручную ужимать соседей, а молчаливое удаление теряло бы работу.

**Отмена через снимки, а не через обратные операции.** Снимок затронутых суток — это десятки блоков;
он одинаково откатывает и правку блока, и раскатку на квартал, и импорт бекапа.

**Даты без часовых поясов.** `YYYY-MM-DD` и минуты от полуночи. Планировщик про сутки человека,
а не про мгновение на глобусе: перевёз сервер в другую зону — разметка не поехала.

**Сетка расширяется вверх сама.** Если блок начинается раньше настроенного начала суток, сетка
показывает его всё равно. Невидимый блок — потерянный блок.

**Живые обновления по SSE.** Поток в одну сторону, переподключение делает браузер. Бэйдж в шапке
показывает настоящее состояние: `synced`, `saving`, `saved` (поток недоступен), `offline`.

**Замок живёт в базе, а не в конфиге.** Пароль в `.env` — это пароль открытым текстом рядом с
compose-файлом, который попадает в бекап конфигов. Поэтому аккаунт заводится при первом заходе и
хранится как scrypt-хеш там же, где разметка: перевёз том — перевёз и доступ.

**«Без пароля» — законный выбор, а не недоделка.** В домашней сети замок часто лишний, и продукт не
делает вид, что это опасная экзотика: кнопка стоит рядом, подтверждается вторым нажатием и честно
пишет, чем это кончится.

**Шрифты самохостятся.** Дизайн-система тянула JetBrains Mono и Inter с Google Fonts — для проекта
про цифровую независимость это было смешно. `npm run fonts` кладёт подмножества (latin, latin-ext,
cyrillic, cyrillic-ext) в `_ds/.../assets/fonts` и переписывает `tokens/fonts.css` на локальные
`@font-face`. Отсутствие внешних запросов проверяется в `npm run smoke`.
