# SHFF Planner

[![ci](https://github.com/Heisenberg4441/shff-planner/actions/workflows/ci.yml/badge.svg?branch=master)](https://github.com/Heisenberg4441/shff-planner/actions/workflows/ci.yml)
[![docker hub](https://img.shields.io/docker/v/heisenberg4441/shff-planner?label=docker%20hub&color=33aa55)](https://hub.docker.com/r/heisenberg4441/shff-planner)

**Поминутный планировщик суток.** Не календарь встреч, а полное расписание дня: сутки — это 1440 минут,
и каждая из них либо размечена, либо видна как дыра. Клик по ячейке ставит блок, дубль растягивает день
на неделю, месяц или квартал.

Self-hosted целиком: один контейнер, один порт, один том. Данные лежат в SQLite на твоём диске,
шрифты — в образе, наружу сервис не ходит ни одним запросом.

```
$ docker compose up -d
$ open http://localhost:8787
```

При первом заходе планировщик спросит, кто здесь хозяин: заводишь администратора (логин и пароль
ложатся в базу, не в конфиг) или выбираешь «использовать без пароля» — для доверенной домашней сети.
Решение меняется потом в настройках, раздел «доступ». Пока выбор не сделан, данные не отдаются никому.

## Что внутри

| Слой | Чем сделан | Зачем так |
|---|---|---|
| Интерфейс | React 19 + TypeScript + Vite | Прототип был одним HTML-файлом со строками стилей в JS; теперь это компоненты и CSS |
| API и хранилище | Node 22 + Fastify 5 + SQLite (better-sqlite3, WAL) | Синхронный драйвер и транзакции: разметка суток не должна разъезжаться |
| Общий домен | `shared/` — чистые функции на обе стороны | Раскатка дней и правила перекрытий обязаны считаться одинаково в UI и на сервере |
| Дизайн-система | `_ds/shff-design-system-*` | Вендорится как есть; продукт расширяет её у себя, а не правит |
| Упаковка | один образ, Node раздаёт и API, и собранный SPA | Никаких сайдкаров с nginx: меньше деталей — меньше поломок |

Что хранится в базе: блоки, категории, шаблоны суток, настройки интерфейса, аккаунт администратора
и журнал операций для отмены. Ничего не держится в localStorage — открыл с телефона, увидел то же самое.

## Запуск

### Одной командой, без репозитория

Образ собирается и публикуется автоматически из ветки `master`:

```bash
docker run -d --name shff-planner \
  -p 8787:8787 -v shff-planner-data:/data \
  --restart unless-stopped \
  heisenberg4441/shff-planner:latest
```

### Docker Compose (так и надо)

```bash
git clone https://github.com/Heisenberg4441/shff-planner.git
cd shff-planner
cp .env.example .env        # необязательно: всё работает и без него

docker compose pull         # взять опубликованный образ
docker compose up -d
docker compose logs -f planner
```

Собрать из исходников вместо готового образа — `docker compose up -d --build`.

Планировщик на `http://localhost:8787`. База — в томе `shff-planner_planner-data`, том переживает
пересборку образа.

Обновление:

```bash
docker compose pull && docker compose up -d   # миграции применятся сами при старте
```

### Без Docker

Нужен Node 22+.

```bash
npm install
npm run build
SHFF_DATA_DIR=./data npm start
```

### Разработка

```bash
npm run dev        # API на :8787 с перезапуском, интерфейс на :5173
npm test           # домен, API и рендер интерфейса
npm run typecheck  # tsc по обоим проектам
npm run smoke      # проверка живого экземпляра (по умолчанию localhost:8787)
```

## Переменные окружения

Все необязательные — сервис поднимается с пустым окружением. Полный список с комментариями лежит
в `.env.example`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SHFF_PORT` | `8787` | Порт внутри контейнера |
| `SHFF_HOST_PORT` | `8787` | Порт на хосте (только для compose) |
| `SHFF_DATA_DIR` | `/data` | Где лежит `planner.db` |
| `SHFF_AUTH_PASSWORD` | — | **Аварийный ключ.** Пусто — доступом распоряжается панель (см. первый запуск). Если задан, перебивает базу: вход только по нему, из панели замок не меняется |
| `SHFF_AUTH_LOGIN` | `admin` | Логин для аварийного ключа |
| `SHFF_SESSION_SECRET` | — | Подпись cookie. Пусто — сгенерируется в `$SHFF_DATA_DIR/session.key` |
| `SHFF_SEED` | `none` | `demo` — засеять примерную неделю вокруг сегодня при первом запуске |
| `SHFF_LOG_LEVEL` | `info` | `fatal … trace`, `silent` |
| `SHFF_TRUST_PROXY` | `false` | Включи, если стоишь за reverse proxy (нужно для честного IP в лимите попыток входа) |
| `TZ` | `Europe/Moscow` | Только логи и `created_at`: даты блоков хранятся как `YYYY-MM-DD` без зоны |

## Как этим пользоваться

**Виды.** `день` — поминутная сетка с ячейками по 15 или 30 минут. `неделя` — семь суток по часам,
клик по колонке открывает день. `месяц` — плотность суток цветной полосой по категориям.

**Поставить блок.** Клик по пустой ячейке. Время можно набрать руками (`9`, `930`, `9:30`, `24:00`),
стрелки ↑↓ в поле шагают по сетке, с Shift — по часу.

**Перекрытия.** Две минуты одного дела не бывает: если новый блок налезает на существующий, тот
уступает место — подрезается по краю, делится на два, если новый лёг в середину, или снимается,
если накрыт целиком. Диалог заранее пишет, что именно случится.

**Раскатка.** `[ Дублировать день → ]` копирует разметку на завтра, до конца недели, на будни,
на весь месяц, на выбранные дни недели или на квартал вперёд. Режим `заменить` очищает сутки-приёмники,
`добавить поверх` кладёт копии, подрезая то, что мешает. Любая раскатка отменяема.

**Отмена.** Каждая операция с разметкой пишет снимок затронутых суток. В тосте есть `[ отменить ]`,
глубина журнала — 50 операций.

**Шаблоны.** Три встроенных (рабочий день, глубокий фокус, выходной) плюс «очистить сутки».
Свой шаблон снимается с любых размеченных суток кнопкой `[ + снять с этих суток ]`.

**Горячие клавиши.** `D` `W` `M` — вид, `N` — новый блок, `C` — дублировать, `T` — сегодня,
`←` `→` — соседние дни, `Esc` — закрыть диалог.

**Настройки** (кнопка в шапке): шаг сетки, начало суток, панели, CRT-слой, категории (название и цвет),
бекап, доступ.

**Доступ.** Первый заход в панель спрашивает один раз: администратор или свободный вход. Логин и пароль
(scrypt, 16 МБ памяти на проверку) лежат в той же базе, что разметка. Дальше в настройках можно поставить
пароль, сменить его или снять — смена и снятие требуют текущий пароль и гасят все выданные сессии.
Забыл пароль — задай `SHFF_AUTH_PASSWORD` в окружении, войди аварийным ключом, поставь новый и убери
переменную.

## Бекап и перенос

Бекап — один JSON со всем содержимым базы:

```bash
curl -o planner-backup.json http://localhost:8787/api/export
```

Восстановление — через `// ДАННЫЕ` в настройках или запросом:

```bash
curl -X POST http://localhost:8787/api/import \
  -H 'Content-Type: application/json' \
  --data-binary @planner-backup.json     # режим по умолчанию — заменить всё
```

Импорт тоже отменяем: перед записью пишется снимок.

Можно бекапить и сам том — сервис держит SQLite в WAL, поэтому копию лучше снимать при остановленном
контейнере либо через `sqlite3 planner.db ".backup"`:

```bash
docker compose stop planner
docker run --rm -v shff-planner_planner-data:/data -v "$PWD:/out" alpine \
  tar czf /out/planner-data.tgz -C /data .
docker compose start planner
```

## За reverse proxy

Планировщик слушает обычный HTTP и ничего не знает про домены. Пример для Caddy:

```caddy
planner.example.org {
  reverse_proxy 127.0.0.1:8787
}
```

Для nginx важно не буферизовать поток событий, иначе живые обновления приедут пачкой:

```nginx
location / {
  proxy_pass http://127.0.0.1:8787;
  proxy_http_version 1.1;
  proxy_set_header Connection '';
  proxy_buffering off;          # SSE
  proxy_read_timeout 1h;
}
```

Если сервис виден из интернета — поставь пароль (первый запуск или настройки → доступ) и включи
`SHFF_TRUST_PROXY=true`: от этого зависит, чей IP попадёт в счётчик попыток входа.

## API

Всё под `/api`, ответы — JSON, ошибки в виде `{ "error": "код", "message": "человеческий текст" }`.
Мутации возвращают `{ days, blocks, op, revision, partial }`: что изменилось и чем это откатить.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | Живость, версия, размер базы. Открыт даже под паролем |
| `GET` | `/api/bootstrap?view=day&date=…` | Всё для загрузки интерфейса одним запросом |
| `GET` | `/api/blocks?from=…&to=…` | Блоки за диапазон (или `?view=week&date=…`) |
| `POST` | `/api/blocks` | Поставить блок. `overlap: trim⎮reject` |
| `PATCH` | `/api/blocks/:id` | Правка; можно менять дату — блок переедет |
| `DELETE` | `/api/blocks/:id` | Снять блок |
| `GET` `PUT` | `/api/days/:date` | Прочитать сутки / заменить целиком (`blocks` или `templateId`) |
| `POST` | `/api/duplicate` | Раскатка: `sourceDate`, `scope`, `mode`, `weekdays`, `blockIds` |
| `POST` | `/api/undo` | Отменить операцию (`opId` или последнюю) |
| `GET` `PATCH` | `/api/settings` | Настройки интерфейса |
| `GET` `POST` `PATCH` `DELETE` | `/api/categories[/:id]` | Категории. Занятую удалить нельзя |
| `GET` `POST` `PATCH` `DELETE` | `/api/templates[/:id]` | Шаблоны суток. `POST {fromDate}` снимает шаблон с суток |
| `GET` `POST` | `/api/export`, `/api/import` | Бекап |
| `GET` | `/api/events` | Поток изменений (SSE) для живого обновления других вкладок |
| `GET` | `/api/auth` | Состояние доступа: настроен ли, режим, вошли ли мы. Открыт всегда |
| `POST` | `/api/auth/setup` | Первый запуск: `{mode:'account',login,password}` или `{mode:'open'}`. Потом — 409 |
| `POST` | `/api/auth/login`, `/api/auth/logout` | Вход и выход |
| `PATCH` | `/api/auth` | Сменить замок: поставить пароль, сменить его (`currentPassword`) или снять |

Пример: поставить блок и сразу его отменить.

```bash
OP=$(curl -sS -X POST localhost:8787/api/blocks -H 'Content-Type: application/json' \
  -d '{"date":"2026-07-30","start":480,"end":720,"title":"Deep: миграция","category":"deep"}' \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).op.id))")
curl -sS -X POST localhost:8787/api/undo -H 'Content-Type: application/json' -d "{\"opId\":\"$OP\"}"
```

```

scripts/         dev.mjs, fetch-fonts.mjs, smoke.mjs

```

Тесты: `shared/test` и `server/test` (домен и API через `app.inject`), `web/src/App.test.tsx`
(рендер интерфейса в jsdom). `npm test` гоняет всё.

### Сборка и публикация

`.github/workflows/ci.yml` на каждый push в `master`:

1. типы (`npm run typecheck`), тесты (`npm test`), сборка (`npm run build`);
2. сборка образа и **прогон смоука по собранному образу** — контейнер поднимается прямо в раннере,
   ему выбирается свободный вход, и `scripts/smoke.mjs` проверяет 22 сценария;
3. только после зелёного смоука — публикация в Docker Hub.

Теги: `latest`, версия из `package.json` (`1.0.0`), короткий SHA коммита. Git-тег `v1.2.3` добавляет
семверные теги `1.2.3` и `1.2`. Пул-реквесты собирают и проверяют образ, но ничего не публикуют.

Нужны два секрета в репозитории: `DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN` (токен с правом
Read & Write в Docker Hub).

Образ пока собирается под `linux/amd64`. Для одноплатников в шаге публикации меняется одна строка —
`platforms: linux/amd64,linux/arm64`; первая сборка под ARM будет долгой, потому что `better-sqlite3`
не публикует готовых бинарей и компилируется из исходников под эмуляцией.

### Про шрифты

Дизайн-система тянула JetBrains Mono и Inter с Google Fonts — для проекта про цифровую независимость
это было смешно. `npm run fonts` скачивает подмножества (latin, latin-ext, cyrillic, cyrillic-ext),
кладёт их в `_ds/.../assets/fonts` и переписывает `tokens/fonts.css` на локальные `@font-face`.
Файлы закоммичены, при загрузке страницы наружу не уходит ни один запрос — это проверяется в `npm run smoke`.

## Решения, которые стоит знать

**Сутки — это разбиение, а не список.** Поэтому перекрытия не запрещены, а разрешаются подрезкой:
запрет заставлял бы вручную ужимать соседей, а молчаливое удаление теряло бы работу.

**Отмена через снимки, а не через обратные операции.** Снимок затронутых суток — это десятки блоков;
он одинаково откатывает и правку блока, и раскатку на квартал, и импорт бекапа.

**Даты без часовых поясов.** `YYYY-MM-DD` и минуты от полуночи. Планировщик про сутки человека,
а не про мгновение на глобусе: перевёз сервер в другую зону — разметка не поехала.

**Сетка расширяется вверх сама.** Если блок начинается раньше настроенного начала суток, сетка
показывает его всё равно. Невидимый блок — потерянный блок.

**Живые обновления по SSE.** Поток в одну сторону, переподключение делает браузер. Бэйдж в шапке
показывает настоящее состояние: `synced`, `saving`, `saved` (поток недоступен), `offline`.

**Замок живёт в базе, а не в конфиге.** Пароль в `.env` — это пароль, который лежит открытым текстом
рядом с compose-файлом и попадает в бекап конфигов. Поэтому аккаунт заводится при первом заходе и хранится
как scrypt-хеш в той же базе, что и разметка: перевёз том — перевёз и доступ. Переменная окружения
осталась только аварийным ключом.

**«Без пароля» — законный выбор, а не недоделка.** В домашней сети замок часто лишний, и продукт не
делает вид, что это опасная экзотика: кнопка стоит рядом, подтверждается вторым нажатием и честно пишет,
чем это кончится.
